# インシデント対応カード（印刷用・1枚）

**原則: 無効化が先。履歴削除は後。値をチャットに貼らない。**

## 気づいたらこの順

1. **push を止める**
2. **漏れた種類をメモ**（値は書かない）
3. **そのサービスのダッシュボードでキー／パスワードを無効化・再発行**
4. **リポジトリからファイル削除 → push**
5. **必要なら GitHub の「Removing sensitive data」手順で履歴掃除**
6. **ローカル進捗メモに日時だけ記録**

## よくある無効化場所

| 種類 | 場所のヒント |
|------|----------------|
| GitHub トークン | github.com → Settings → Developer settings |
| Google API | console.cloud.google.com → API とサービス → 認証情報 |
| Play アップロード鍵 | play.google.com/console → 対象アプリ → テストとリリース → アプリ署名 |
| サイトのデプロイトークン | 使っているホスト（Cloudflare / ChatGPT site 等）のトークン画面 |

## やってはいけない

- 漏れた鍵を「まだ使えるか」と試すために再 push する  
- 公開 Issue に鍵の全文を貼る  
- `git push --no-verify` で検査をスキップする  
- 無効化前に「履歴から消したから大丈夫」と思い込む  

## 検査コマンド

```powershell
pwsh -File scripts/security-check.ps1
```

PASS 以外は公開作業を中断。
